# 携程旅行网 - 忘记密码模块需求文档

## 1. 忘记密码模块

### 1.1 密码重置流程

#### 1.1.1 进入方式
- 用户在账号密码登录页面点击"忘记密码"链接。
- 系统直接跳转至忘记密码页面的第一步。

#### 1.1.2 页面元素

**步骤1：填写账号**
- **进度指示器**：显示三个步骤："填写账号" -> "验证" -> "重置密码"，当前步骤为"填写账号"。
- **账号输入框**：标签为"账号"，占位符显示"手机号/用户名/邮箱/卡号"（实际只验证手机号格式）。
- **提示文字**："境外手机请输入国家码-手机号，如852-18616666666"。
- **"下一步，验证"按钮**：橙色按钮，点击后验证手机号是否已注册。
- **Header 和 Footer**：保持与登录页面一致的布局。

**步骤2：验证**
- **进度指示器**：当前步骤为"验证"。
- **账号显示框**：只读显示框，标签为"账号"，显示脱敏后的手机号（如"155****5343"）。
  - 脱敏规则：前3位 + 4个星号 + 后4位
  - 背景色为灰色，表示不可编辑
- **绑定手机显示**：文本显示"绑定手机 86-155****5343"。
- **验证码输入框**：占位符为"6位数字"。
- **"发送验证码"按钮**：蓝色文字链接，点击后向手机号发送验证码。
  - 发送后变为"60秒后重新发送"，并开始倒计时
  - 倒计时期间按钮不可点击
  - 倒计时结束后恢复为"发送验证码"
- **"下一步，重置密码"按钮**：橙色按钮，点击后验证验证码是否正确。
- **"< 返回上一步"链接**：点击后返回步骤1。

**步骤3：重置密码**
- **进度指示器**：当前步骤为"重置密码"。
- **新密码输入框**：
  - 标签为"新密码"
  - 占位符为"请设置新密码"
  - 右侧有眼睛图标，点击可切换显示/隐藏密码
  - 默认密码以圆点（•）形式显示
- **确认密码输入框**：
  - 标签为"确认新密码"
  - 占位符为"再次输入密码"
  - 右侧有眼睛图标，点击可切换显示/隐藏密码
- **密码强度指示器**：三个并列的矩形框，显示"弱"、"中"、"强"。
  - 未输入或不符合要求时，三个矩形均为灰色
  - 根据密码复杂度，橙色矩形依次亮起：
    - 弱：只有"弱"矩形亮起（1-2项：长度、大写、小写、数字、符号）
    - 中：前两个矩形亮起（3-4项）
    - 强：三个矩形全部亮起（5项）
- **提示文字**："密码需为8-20位字母、数字和符号的组合，不含空格"。
- **"完成"按钮**：橙色按钮，点击后提交新密码。
- **"< 返回上一步"链接**：点击后返回步骤2。

**步骤4：完成提示（不显示在进度指示器中）**
- **成功提示**：页面底部显示黑色半透明提示框："密码重置成功"。
- **自动跳转**：2秒后自动跳转至登录页面。

#### **场景描述 (Gherkin)**

#### 步骤1：填写账号相关场景

**Scenario: 1.1.3 用户输入已注册的手机号成功进入步骤2**
    Given 用户已打开忘记密码页面，进入步骤1
    And 用户输入了一个已注册的合法手机号
    When 用户点击"下一步，验证"按钮
    Then 系统验证手机号已注册
    And 页面跳转至步骤2（验证）
    And 进度指示器更新为"验证"步骤

**Scenario: 1.1.4 用户输入未注册的手机号**
    Given 用户已打开忘记密码页面，进入步骤1
    And 用户输入了一个未注册的合法手机号
    When 用户点击"下一步，验证"按钮
    Then 系统显示错误提示："该手机号未注册"
    And 页面停留在步骤1

**Scenario: 1.1.5 用户输入不合法的手机号**
    Given 用户已打开忘记密码页面，进入步骤1
    And 用户输入了一个不合法的手机号，如"123"
    When 用户点击"下一步，验证"按钮
    Then 系统显示错误提示："手机号格式不正确"
    And 页面停留在步骤1

**Scenario: 1.1.6 用户未输入账号点击下一步**
    Given 用户已打开忘记密码页面，进入步骤1
    And 用户未输入任何内容
    When 用户点击"下一步，验证"按钮
    Then 系统显示错误提示："请输入手机号"
    And 页面停留在步骤1

#### 步骤2：验证相关场景

**Scenario: 1.1.7 用户成功发送验证码**
    Given 用户已进入步骤2（验证）
    And 页面显示脱敏后的手机号（如"155****5343"）
    When 用户点击"发送验证码"按钮
    Then 系统向该手机号发送一条包含6位数字验证码的短信（类型为'reset'）
    And 按钮文字变为"60秒后重新发送"
    And 开始60秒倒计时
    And 倒计时期间按钮不可点击

**Scenario: 1.1.8 用户输入正确的验证码成功进入步骤3**
    Given 用户已进入步骤2（验证）
    And 用户已成功发送验证码
    And 用户在验证码输入框中输入了正确的6位数字验证码
    When 用户点击"下一步，重置密码"按钮
    Then 系统验证验证码正确且未过期
    And 页面跳转至步骤3（重置密码）
    And 进度指示器更新为"重置密码"步骤

**Scenario: 1.1.9 用户输入错误的验证码**
    Given 用户已进入步骤2（验证）
    And 用户已成功发送验证码
    And 用户在验证码输入框中输入了错误的验证码
    When 用户点击"下一步，重置密码"按钮
    Then 系统显示错误提示："验证码错误或已过期"
    And 页面停留在步骤2

**Scenario: 1.1.10 用户未输入验证码点击下一步**
    Given 用户已进入步骤2（验证）
    And 用户未输入验证码
    When 用户点击"下一步，重置密码"按钮
    Then 系统显示错误提示："请输入验证码"
    And 页面停留在步骤2

**Scenario: 1.1.11 用户在倒计时结束前重复点击发送验证码**
    Given 用户已进入步骤2（验证）
    And 用户已点击"发送验证码"按钮
    And 倒计时尚未结束（如还剩30秒）
    When 用户再次点击"发送验证码"按钮
    Then 按钮无响应，系统不发送新的验证码
    And 倒计时继续

**Scenario: 1.1.12 用户点击"返回上一步"**
    Given 用户已进入步骤2（验证）
    When 用户点击"< 返回上一步"链接
    Then 页面跳转回步骤1（填写账号）
    And 进度指示器更新为"填写账号"步骤
    And 之前输入的手机号仍保留在输入框中

**Scenario: 1.1.13 验证码过期**
    Given 用户已进入步骤2（验证）
    And 用户已成功发送验证码
    And 验证码已过期（如15分钟后）
    And 用户输入了该验证码
    When 用户点击"下一步，重置密码"按钮
    Then 系统显示错误提示："验证码错误或已过期"
    And 页面停留在步骤2

#### 步骤3：重置密码相关场景

**Scenario: 1.1.14 用户成功重置密码**

### 1.2 API 接口规范

#### 1.2.1 步骤1：验证手机号是否已注册

**接口地址**：`POST /api/auth/reset-password/step1`

**请求参数**：
```json
{
  "phone": "15512345678"
}
```

**成功响应**（200）：
```json
{
  "success": true,
  "message": "手机号验证成功"
}
```

**失败响应**（400）：
```json
{
  "success": false,
  "error": "该手机号未注册"
}
```

**验证规则**：
- 手机号必须为11位数字
- 手机号必须以1开头
- 手机号必须已在系统中注册

#### 1.2.2 发送验证码

**接口地址**：`POST /api/auth/send-code`

**请求参数**：
```json
{
  "phone": "15512345678",
  "type": "reset"
}
```

**成功响应**（200）：
```json
{
  "success": true,
  "message": "验证码已发送"
}
```

**失败响应**（400）：
```json
{
  "success": false,
  "error": "发送验证码过于频繁，请稍后再试"
}
```

**验证规则**：
- type 必须为 'reset'
- 同一手机号60秒内只能发送一次验证码
- 验证码有效期为15分钟

#### 1.2.3 步骤2：验证验证码

**接口地址**：`POST /api/auth/reset-password/step2`

**请求参数**：
```json
{
  "phone": "15512345678",
  "code": "123456"
}
```

**成功响应**（200）：
```json
{
  "success": true,
  "message": "验证码验证成功"
}
```

**失败响应**（400）：
```json
{
  "success": false,
  "error": "验证码错误或已过期"
}
```

**验证规则**：
- 验证码必须为6位数字
- 验证码必须与手机号匹配
- 验证码必须未过期
- 验证码类型必须为 'reset'

#### 1.2.4 步骤3：重置密码

**接口地址**：`POST /api/auth/reset-password/step3`

**请求参数**：
```json
{
  "phone": "15512345678",
  "password": "Pass123!@#"
}
```

**成功响应**（200）：
```json
{
  "success": true,
  "message": "密码重置成功"
}
```

**失败响应**（400）：
```json
{
  "success": false,
  "error": "密码必须至少8位且包含字母和数字"
}
```

**验证规则**：
- 密码长度必须为8-20位
- 密码必须包含字母和数字
- 密码不能包含空格

### 1.3 前端组件规范

#### 1.3.1 组件结构
- **ForgotPasswordForm.jsx**：主表单组件，管理三个步骤的状态和切换。
- **ForgotPasswordForm.module.css**：组件样式文件。

#### 1.3.2 状态管理
```javascript
const [step, setStep] = useState(1)  // 当前步骤：1, 2, 3, 4
const [phoneNumber, setPhoneNumber] = useState('')  // 手机号
const [verificationCode, setVerificationCode] = useState('')  // 验证码
const [password, setPassword] = useState('')  // 新密码
const [confirmPassword, setConfirmPassword] = useState('')  // 确认密码
const [countdown, setCountdown] = useState(0)  // 倒计时
const [passwordStrength, setPasswordStrength] = useState('')  // 密码强度
const [error, setError] = useState('')  // 错误信息
```

#### 1.3.3 关键功能
- **手机号脱敏**：`maskPhone(phone)` 函数将手机号转换为 "155****5343" 格式。
- **密码强度检测**：`checkPasswordStrength(password)` 函数返回 'weak'、'medium' 或 'strong'。
- **验证码倒计时**：使用 `useEffect` 和 `setInterval` 实现60秒倒计时。
- **步骤导航**：支持前进（下一步按钮）和后退（返回上一步链接）。

### 1.4 安全性要求

1. **验证码安全**：
   - 验证码类型隔离：reset 类型的验证码不能用于 login 或 register
   - 验证码使用后立即失效
   - 验证码过期时间为15分钟

2. **密码安全**：
   - 密码必须经过 bcrypt 加密后存储
   - 密码强度要求：至少8位，包含字母和数字

3. **防止用户枚举**：
   - 错误提示应避免暴露用户是否存在
   - 但在步骤1中，为了用户体验，明确提示"该手机号未注册"

4. **频率限制**：
   - 同一手机号60秒内只能发送一次验证码
   - 防止暴力破解验证码

### 1.5 UI/UX 要求

1. **进度指示器**：
   - 清晰显示当前步骤
   - 已完成步骤显示为蓝色
   - 当前步骤显示为高亮
   - 未完成步骤显示为灰色

2. **错误提示**：
   - 使用红色背景的 ErrorMessage 组件
   - 错误信息简洁明确
   - 显示在相关输入框附近

3. **交互反馈**：
   - 按钮点击后显示加载状态
   - 验证码倒计时实时更新
   - 密码强度实时反馈
   - 成功提示使用黑色半透明弹窗

4. **响应式设计**：
   - 支持桌面和移动端显示
   - 按钮和输入框大小适配不同屏幕

5. **无障碍性**：
   - 所有输入框有明确的标签
   - 按钮有清晰的文字说明
   - 支持键盘导航
